# Самопроверка на данных объекта

Проверяет, что Атлас правильно прочитал ваши файлы и посчитал по ним, не по демо-данным.

## Запуск

Windows: перетащите папку с файлами объекта на `check_data_windows.bat`.

Из консоли:

```
python -m atlas.selfcheck "D:\Данные\Объект" --out selfcheck_result
```

Параметры: `--quick` (без независимой сверки и повторной загрузки, быстрее), `--recursive` (искать во вложенных папках),
`--production-unit` и `--gdi-unit` (единица расхода, если её нет в заголовке; по умолчанию м³/сут и тыс. м³/сут).

Файлы читаются, но не изменяются. Проект создаётся во временной папке и удаляется.

## Что проверяется

Для каждого файла:
- файл распознан и не блокируется служебными листами;
- загруженные строки и суммы расхода совпадают с независимым пересчётом из исходной таблицы (по файлу в целом и по каждой скважине);
- нет пустых, отрицательных и будущих значений; нет повторов «скважина + сутки»; составные номера («54/80») разделены;
- скважина в одной группе; группы заполнены; нет одновременных отбора и закачки; сезон согласован с датой;
- порядок величин расхода; пропуски суток; сутки «открыта, расхода нет»;
- ГДИ: ΔP² = Рпл² − Рзаб², Рзаб ≤ Рпл, расход положителен, индикаторные кривые физичны.

Для объекта в целом:
- скважины ГДИ есть в добыче, названия групп совпадают;
- все модули считаются без сбоев и без нечисловых значений;
- суммы групп на графиках равны сумме исходных расходов;
- поскважинный анализ считается;
- повторная загрузка ничего не удваивает.

## Результат

`selfcheck_report.md` — для чтения, `selfcheck_report.json` — для разбора (его можно отправить в чат).
В отчёте только счётчики, номера скважин и даты; таблицы не копируются.
Статусы: «ОШИБКА» — расхождение, которое надо объяснить; «Внимание» — сомнительное место; «Сведения» — факт о данных;
«Пройдено»; «Пропущено» — проверка неприменима (например, нет ГДИ).
