# Аудит: где программа решает за инженера (2026-10-20)

Принцип: финальное слово по любому вопросу за инженером. Программа — помощник и советчик: автоматика допустима
только как подсказка с видимой причиной и с возможностью переопределить вручную.

Охват: `gas_atlas` (Атлас 6, `atlas/`) и `all_scripts` (`pxg_base/`, `pxg_core/`). Адаптация на ГДИ (ручной выбор
исследований) — отдельный тред, здесь не разбирается.

## Находки

Приоритет: **высокий** — молча меняет или отбрасывает данные; **средний** — решение принято без выбора инженера,
но видно в журнале; **низкий** — правило заложено в код без возможности изменить.

## Что сделано в этом PR

Только аудит. Код не менялся. Исправления выбраны по порядку пунктов 1–3 и вынесены в следующие PR.

## План по пункту 3 (давление по группам из опорной сетки)

1. Загрузка: в Атлас импортировать пересчитанные Рпл (скважина, дата, давление) из БД «База давлений по замерам» /
   «Пересчёт давлений»; сопоставление скважина → группа брать из `data.mapping` (как сейчас для расходов).
2. Опорная сетка: скважины с группой из `mapping`; среднее по группе на дату; давление объекта — среднее по
   опорной сетке, если нет столбца «Рпл объекта» в исходнике (приоритет у прямого столбца).
3. Инженер видит список опорных скважин и может исключить/добавить вручную (через существующий ручной фильтр).
4. График «Динамика давлений по группам» в «Авторском надзоре», глава 2, табл. и тест.

Открыто для инженера: какой файл БД считать источником (пересчёт или «База давлений по замерам»), и нужна ли
сетка, отличная от `WELL_GROUPS` из `замеры.py`.
