# Передача: конструктор графиков, этап 4 — преобразования и калькулятор (до 15 строк)

- **Цель раздела:** свой график из любых полей проекта (план и решения Egor — `chart-builder/plan.md`, этапы 1–5).
- **Сделано:** этапы 1–3 (каркас, окна, комбинированные виды). Этап 4 — преобразование ряда (накопленное, скользящее, по суткам/месяцам/скважинам,
  нормировка, ×/÷/+ число, разность) и ряд-формула по буквам рядов (A/B, (A-B)/A*100, функции abs/sqrt/ln/log10/exp/min/max/mean).
- **Файлы этапа 4:** новый `atlas/modules/builder_calc.py` (преобразования, разбор и вычисление формул, выравнивание по ключу), `builder.py`
  (`Row.source/formula/transform/unit`, `Calc`, `_calc_row` с памятью — скрытые ряды считаются для формул), `web/src/builderFormula.ts`
  (проверка на лету, циклы, перенумерация букв), `ChartBuilder.tsx` (`FormulaFields`, `TransformFields`), `builder.css`, тесты `test_builder_calc.py`.
- **Решения:** макет без смены версии: новые поля необязательны. Формула — свой рекурсивный спуск, без eval; ошибки разбора и циклы — `ParamError`
  с номером ряда; деление на ноль и т. п. — пропуск точки и заметка. Точки формулы = точки первого ряда в ней. Ядро не тронуто: общих функций
  преобразования рядов в `atlas/engine/modules/` нет (там накопленное — `cumsum()/1e6` внутри разделов), сделано тем же способом в представлении.
- **Открытые вопросы:** накопленное — сумма значений (верно для суточных рядов, иначе заметка); единица формулы только ручная; ряды в формуле
  с числовым X сопоставляются по скважине/дате, не по X; перенумерация букв — только при удалении и дублировании (перестановки рядов нет).
- **Следующий шаг:** этап 5 — сохранение макетов в проекте (storage/, с версией), список, выгрузка Word/PNG/данные, вставка в отчёт АН.
- **Проверка:** `python -m pytest -q tests/atlas/test_builder*.py`; `cd web && npx tsc --noEmit && npm run build`
