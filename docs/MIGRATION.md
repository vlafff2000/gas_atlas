# Перенос исходного функционала

Источники: `Gas_Atlas_Python.zip`, `Копия (1) Анализ_ГДИ_ФИНАЛ_без_линии_тренда.py`, `графики_реагирования_контрольные_горизонты.py`. Архив `Gas_Atlas_v2_Linux.zip` содержал начальную заготовку интерфейса.

## Динамика

Из первой рабочей версии перенесены правила накопленного объема всего объекта, средних только по положительным расходам, взвешенного рейтинга, матричного и длинного импорта, типов отбора/закачки, явных сезонов и годов, групп и подгрупп. Добавлены постоянные проекты, единая палитра по давности периодов, PDF, общий экспорт и самостоятельная вкладка времени Q(t).

## ГДИ

В `legacy_fit.py` дословно сохранен метод `GDIAnalyzer.fit_trend_line` из исходного скрипта: прямая регрессия `ΔP² = aQ + bQ²` через `scipy.optimize.curve_fit`, положительные границы 1e-10, начальная линеаризация и исходный запасной вариант. Внешний адаптер отбрасывает нечисловые/бесконечные значения и отказывается от неидентифицируемого подбора при одинаковых Q. Выбор БД/расчета повторяет исходный приоритет по порогу R².

В исходном файле были разные стратегии для графиков и таблиц, повторные определения методов и консольный/Tkinter-интерфейс. Новое приложение показывает расчетную и БД-кривую независимо и указывает выбранные коэффициенты в таблице. Автоматический переход на прямую при плохом подборе убран: плохое качество не маскируется другим уравнением.

Исправлены:

- Независимая сортировка Q и ΔP² при сравнении исследований: теперь сортируются связанные пары. Повторные Q для интерполяции объединяются средним ΔP², исходные точки для подбора остаются неизменными.
- Приведение всех номеров скважин к `int`: буквенные индексы и ведущие нули строковых идентификаторов сохраняются.
- Пустой R² больше не форматируется как число; одинаковые расходы не дают произвольную пару коэффициентов.
- Исследования разных методов/номеров не смешиваются. Даты не переписываются автоматически на основании имени файла.

В исходном коде переменная `q_max` использовалась как верхняя граница диапазона графика. Она не была расчетом абсолютного свободного дебита. Поэтому в новой версии отдельно названы **наблюдаемый Qmax** и **формальный Qсв при Рзаб=0**; второй является новым расчетом и сопровождается условиями применимости.

Сравнение трех последних исследований и программа фонда доступны в интерфейсе. Эвристические исходные категории «хорошее/плохое КРС» не выдаются как установленная причина изменения: выводится направление изменения трех исследований. Это явное изменение интерпретации, а не изменение аппроксимации a и b.

## Реагирование

Сохранены уровни по скважинам и горизонтам, временные ряды, обратная ось глубины и экспорт. Выбор рабочего/контрольных горизонтов перенесен в интерфейс; приведенное давление строится отдельно, чтобы не смешивать метры и давление на одной оси. Удаление всех нечисловых символов заменено проверкой одного числа с единицей: текст `10–20 м` не превращается в уровень 1020 м.

## Новые механизмы

Проверка импорта с журналом строк, Parquet-снимки, SQLite-история, контроль конкурентного редактирования, резервные копии, перенос v1 JSON, единый экспорт и набор воспроизводимых тестов.


## Версия 4.0 для Python 3.8

Полный функционал версии 3.0 сохранен. Математический алгоритм `legacy_fit.py` не изменялся. Зафиксированы совместимые зависимости, включая Streamlit 1.40.1, pandas 2.0.3, SciPy 1.10.1 и Matplotlib 3.7.5.

Изменения реализации:

- Новые установщики и запуск для Linux и Windows; проверка CPython 3.8 x64 до установки. В Linux виртуальное окружение использует ссылки на интерпретатор, что поддерживает отдельные переносимые установки Python.
- Межплатформенная блокировка проекта через portalocker; соединения SQLite закрываются после каждой операции. Удаление старого снимка повторяется позже, если Windows удерживает открытый файл.
- Загрузчик дат Excel преобразует числовые серии в float64 перед передачей pandas; пустые серии пропускаются. Русские даты и числовые даты Excel сохраняют прежнее значение.
- Применение импорта выполняется через callback, после чего страница читает новую ревизию проекта. Сообщение об успешном сохранении остается видимым.
- Интерфейс использует API Streamlit 1.40; лимит загрузки 512 МБ задается в конфигурации сервера. Темная тема дополнена светлыми графиками.
- Установщик использует единый lock-файл, включая условные Windows-зависимости. Dockerfile использует Python 3.8.20.


## Версия 5.0 · Python 3.8.20

Исходная математическая функция `legacy_fit.py` сохранена. Перед расчетом применяется обратимый ручной фильтр. Идентификаторы измерений строятся по логическим ключам, у ГДИ — также по паре Q/ΔP² и номеру одинакового измерения. Они не зависят от индекса DataFrame или номера экранной точки.

В динамике исключенная строка остается в исходном наборе, но ее рабочий расход становится NaN: она не входит в средние и накопление, на кривой образуется разрыв. Уровень и давление реагирования имеют отдельные идентификаторы показателей; выключение одного не затрагивает другой. ГДИ пересчитывается по оставшимся исходным точкам; коэффициенты БД остаются отдельным независимым вариантом отображения.

Настройки `excluded_points` хранят журнал идентификаторов и исходных значений; резервная копия включает его вместе с неизмененными исходными таблицами. Удаление исключения полностью восстанавливает наблюдение. Перенос v4 не требует преобразования таблиц.

Статические графики реагирования с двумя шкалами теперь экспортируются через независимые оси Matplotlib. Предпросмотр статического файла и экспорт используют один рендерер. Интерактивный просмотр сохраняет Plotly, подсказки и клики. Подробнее о пользовательских изменениях: CHANGES_v5.md.
