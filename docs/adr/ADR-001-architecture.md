# ADR-001. Архитектура Gas Atlas 6: Python-ядро + веб-интерфейс

Дата: 2026-10-03. Статус: принято.

## Контекст
Gas Atlas 5.8 написан на Streamlit. Он перезапускает скрипт страницы на каждое взаимодействие, поэтому
потребовались кэши (`performance.py`), а `main.py` вырос до разбора всех страниц. Нужно подключить
десятки отдельных скриптов автора надзора (ГДИ, КРС, ГИС, давления, ГВК, герметичность, экология) под
единый удобный интерфейс. Приоритеты: скорость отклика и гибкость интерфейса. Запуск: окно приложения на Windows, данные локально.

## Решение
1. **Ядро на Python** (пакет `atlas/`): pandas/numpy/scipy, модули расчёта, хранилище, API на Starlette.
2. **Интерфейс — веб-приложение (React + TypeScript)** общается с ядром по HTTP/JSON. Графики рисуются в браузере.
   Окно на Windows — оболочка (pywebview) вокруг того же сайта; ядро и интерфейс не знают об оболочке.
3. **Контракт модуля** (`atlas/contract.py`): модуль = класс с декларативным `spec` (параметры, нужные данные) и чистым
   методом `run(data, params) -> Result` (таблицы, графики, заметки). Интерфейс не импортирует модули: он читает
   `GET /api/modules` и строит панель параметров и вывод обобщённо. Новый скрипт подключается файлом в
   `atlas/modules/` без правок интерфейса.
4. **Доменная модель ПХГ** (`atlas/domain.py`): фонд скважины (эксплуатационная / наблюдательная / контрольная),
   горизонт, группа, виды наборов данных. Все модули говорят на одном словаре.
5. **Математика не переписывается.** Проверенные расчёты (например, `app.modules.gdi`) вызываются как есть;
   новый модуль добавляет выбор данных и представление. Паритет с прежними функциями закреплён тестами
   (`tests/atlas/test_gdi_module.py`: совпадение коэффициентов с точностью до бита).
6. Старое Streamlit-приложение остаётся рабочим, пока модули не перенесены; затем удаляется.

## Почему не остальное
- **Остаться на Streamlit**: потолок по скорости и по построению интерфейса остаётся.
- **NiceGUI / Dash**: проще, но ниже потолок по скорости графиков и дизайну; для десятков модулей с общей рамкой это упирается в те же ограничения.

## Последствия
- Нужны Node для сборки интерфейса (только у разработчика; у пользователя собранная папка `atlas/web/dist`).
- Python для ядра — 3.8+ (изначально было 3.10+; снижено 2026-10-03: компьютеры компании держат 3.8, проверено тестами на 3.8.20).
- Единый формат результата (`Result`) даёт один экспорт в Excel/PNG для всех модулей.

## Следующие шаги
Хранилище проектов (перенос `app/core/storage.py`), каркас React (навигация по `spec.group`, панель параметров,
таблицы, графики), перенос ГДИ-экспорта, затем остальные страницы и ваши скрипты.
