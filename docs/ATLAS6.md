# Газовый атлас 6: каркас

Решение и причины — в [ADR-001](adr/ADR-001-architecture.md). Здесь — как запускать и как подключать модули.

## Запуск

Windows: `run_atlas_windows.bat` (нужен Python 3.12+ в `.venv`; недостающие пакеты поставит
`tools/install.py`: на 3.13 — `requirements-lock-py313.txt`, на 3.12 — `requirements-atlas.txt`). Открывается окно приложения (pywebview).
Linux: `bash run_atlas.sh` — то же в браузере.

Вручную: `python -m atlas` (окно), `python -m atlas --browser`, `python -m atlas --server` (только ядро на порту 8765).

Проекты хранятся в папке `storage/` (формат прежней версии 5.8, проекты из неё открываются без миграции). Для пробы без своих данных в 6 есть кнопка «Открыть демонстрационный объект».

### Большой демо-объект (проверка скорости)
Синтетика в формате импорта, строится заново при каждом запуске (в git не хранится):
отбор и закачка 1 000 000 строк, ГДИ 300 000, реагирование 200 000, кроссплот давлений 500 000 пар.

- в 6: «Проекты» → «Создать большой демо-объект (2 млн строк)» (или та же кнопка на пустом экране);
- из командной строки (Python 3.12+): `python tools/make_large_demo.py`, объёмы меняются ключами
  `--production --gdi --response --pressure` (0 — набор не создаётся), `--seed`, `--storage`;
- замер скорости: `python tools/benchmark_large_demo.py` (создаёт демо во временной папке).

## Устройство

```
atlas/
  contract.py   контракт модуля: ModuleSpec, Param, Result (Table, Chart, Note)
  domain.py     словарь ПХГ: фонд скважин, виды наборов данных, колонки, единицы
  registry.py   находит модули в atlas/modules/ сам
  projects.py   проекты: адаптер к atlas/engine/core/storage.py, кэш данных в памяти, исключённые точки
  api.py        HTTP/JSON (Starlette), раздаёт и собранный интерфейс
  __main__.py   запуск: сервер + окно
  modules/      по файлу на модуль: gdi.py, production.py, histograms.py (общее — _production.py), response.py
  web/dist/     собранный интерфейс (в git, чтобы пользователю не нужен был Node)
web/            исходники интерфейса: React + TypeScript + ECharts
tests/atlas/    тесты ядра; паритет ГДИ с 5.8 — побитовый
```

API:

| Запрос | Что делает |
|---|---|
| `GET /api/modules` | описания всех модулей (`spec`) — из них интерфейс строит навигацию и панели |
| `GET /api/projects` | список проектов |
| `POST /api/projects/demo` | создать демонстрационный объект; `{"large": true, "rows": {...}}` — большой (`atlas/engine/core/demo_large.py`) |
| `GET /api/projects/{id}/options?dataset=gdi&column=well` | варианты для списков выбора |
| `POST /api/modules/{id}/run` `{project, params}` | расчёт, ответ — `Result` в JSON |
| `POST /api/modules/{id}/export` `{project, params, target, id, format, dpi, font, font_size}` | график (SVG/PDF/PNG) или таблицы (XLSX, одна таблица — CSV) |
| `GET /api/projects/{id}` | сводка проекта: ревизия, наборы данных, общие настройки, число исключений |
| `PATCH /api/projects/{id}/settings` `{values}` | общие настройки: `r2_threshold`, `season_start/end`, `auto_seasons` + `season_gap_days` + `season_rate_share` (автоопределение сезонов по накопленному расходу, `app/modules/seasons.py`; по умолчанию выключено), `manometer_wells`, `visible_pages`, `chart_style`, `working_horizons`, `export_any` (Экспорт → «Любой график»: последний выбор и настройки выгрузки каждого графика по ключу «раздел::график»; график без своих настроек берёт вид рядов и границы осей с экрана); проекты, копии, резервные копии, выгрузки — `atlas/api_projects.py`, экспорт — `atlas/api_export.py` |
| `GET /api/projects/{id}/versions` | копии данных проекта: перед каждым импортом сохраняется прежнее состояние, хранятся последние 10 (`GAS_ATLAS_SNAPSHOTS`) |
| `POST /api/projects/{id}/rollback` `{snapshot, revision}` | вернуть данные копии новой ревизией (история и настройки остаются); `snapshot: "none"` — проект без данных. Ответ импорта содержит `undo.snapshot` — копию до него («Откатить этот импорт») |
| `POST /api/projects/{id}/exclusions` `{dataset, add, remove, reason}` | исключить / вернуть точки (журнал как в 5.8) |
| `POST /api/projects/{id}/exclusions/undo` | отменить последнее исключение |
| `POST /api/projects/{id}/exclusions/state` `{at, side, revision}` | «История фильтра»: восстановить состояние до / после изменения (`atlas/api_exclusions.py`) |
| `POST /api/projects/{id}/groups` `{changes, action}` | группы и подгруппы скважин (`manifest.groups`, формат 5.8) |
| `GET/POST /api/projects/{id}/state/{module}?panel=N` | сохранённый вид панели и «Расчет …» в истории (формат 5.8) |
| `POST /api/modules/{id}/options` `{project, param, params}` | варианты зависимого списка |
| `GET /api/projects/{id}/passport?well=`, `POST …/passport/comment`, `POST …/passport/pdf` | «Паспорт скважины» (`atlas/api_passport.py`) |
| `POST /api/projects/{id}/well-filter` `{filter}`, `GET …/options?…&filter=` | фильтр скважин вкладки: сколько скважин остаётся; списки значений только по оставленным скважинам. Сам фильтр — `params.well_filter` = `{groups, wells}` в запросах расчёта, списков и сохранения вида (у каждой вкладки свой, пресеты общие), см. `atlas/well_filter.py` |
| `POST /api/projects/{id}/import/ggh`, `…/ggh/apply`; `POST …/export/ggh` | данные ГГХ и Word с графиками ГГХ для отчёта, см. `docs/GGH.md` |
| `/api/import/*`, `/api/projects/{id}/import/*` | импорт данных (файлы → распознавание → проверка → применение), см. `atlas/api_import.py` и `docs/parity/import.md` |

Ошибки приходят как `{"error": "текст для пользователя"}`: 400 — неверный параметр,
404 — нет проекта или модуля, 409 — в проекте нет нужных данных, 500 — сбой модуля (подробности в журнале).

## Как подключить скрипт

Создайте файл `atlas/modules/<имя>.py`. Интерфейс и API менять не нужно.

```python
from atlas.contract import Module, ModuleSpec, Param, Option, Source, Result, Table, Chart, Axis, Series, Note
from atlas.domain import DatasetKind

class WaterControl(Module):
    spec = ModuleSpec(
        id='water', title='Контроль воды', group='Эксплуатация',
        needs=(DatasetKind.WATER,),
        params=(
            Param('wells', 'Скважины', 'multi', default=[], source=Source(DatasetKind.WATER, 'well')),
            Param('limit', 'Порог воды', 'number', default=1.0, minimum=0, unit='м³/сут'),
        ),
    )

    def run(self, data, params):
        d = data[DatasetKind.WATER]
        if params['wells']:
            d = d[d.well.isin(params['wells'])]
        # ... расчёт: здесь вызывается существующая функция скрипта
        return Result(tables=[Table('rows', 'Замеры', d)])
```

Правила:

1. `run` — чистая функция: не пишет файлы, не держит состояние, не меняет входные таблицы.
2. Проверенная математика вызывается как есть; новый код — только выбор данных и представление.
3. Для перенесённого раздела — чек-лист функций в `docs/parity/<раздел>.md` и тест паритета со старыми функциями
   (пример: `docs/parity/gdi.md`, `tests/atlas/test_gdi_module.py`). Раздел готов, когда закрыт весь чек-лист.
4. Тексты для пользователя — по-русски, в заметках (`Note`) объясняется, что делать, а не только что случилось.
5. Пустая выборка — заметка, а не исключение.

Виды параметров: `number`, `integer`, `boolean`, `choice` (варианты в `options`), `multi`
(варианты в `options` или из данных через `source`), `date` (строка `ГГГГ-ММ-ДД`; пусто — без границы или умолчание модуля), `text` (многострочный текст).
Пустой `multi` по соглашению означает «все».
`section` группирует параметры на панели; `setting` привязывает параметр к общей настройке проекта.

Что модуль может вернуть, кроме таблиц и графиков:
- точки графика с `ids` и `dataset` — щелчок в режиме «Исключать точки кликом» исключает точку;
- `Table.action` — флажки в строках и кнопка применения (ручной фильтр, подтверждение выбросов);
- `TableAction(kind='assign')` — правка ячеек и запись групп скважин в проект;
- `Table.note`, `Table.collapsed`, `Note` — пояснения и свёрнутые таблицы;
- столбцы (`Series.kind='bar'`, ось `scale='category'`), ящики с усами (`Series.kind='box'`: y — пять чисел на категорию),
  заданные границы оси (`Axis.minimum` / `maximum`), подсказка на каждую точку (`Series.labels`), штрихи и толщина линий;
- линии с точками (`Series.markers`, полые — `hollow`), вторая шкала справа (`Chart.y2`, серия с `axis='y2'`), обратная ось (`Axis.inverse`).

Зависимые списки: `Param(dynamic=True, depends=('kind',), auto='last:3')` и метод `Module.options(name, data, params)` —
интерфейс спрашивает варианты у модуля при смене параметров, из которых они зависят, отбрасывает недопустимое
и подставляет выбор по умолчанию (`'all'`, `'first:10'`, `'last:3'`). `Param.show_if` скрывает параметр в других режимах.
`ModuleSpec.panels=2` включает «две независимые панели»; ключ сохранённого вида на панель задаёт `Module.panel_key`.

`data[kind]` — данные без исключённых точек, `data.raw[kind]` — все исходные (с `_point_id`),
`data.excluded` — журнал исключений.

## Графики

Все графики рисует `web/src/ChartView.tsx` (ECharts); оформление — `chartTheme.ts` и `chart.css`, подсказка — `chartHover.ts`.
- Подсказка следует за курсором: «Плавно» — значения кривых между замерами (линейная интерполяция, у логарифмической
  оси — по логарифму), «Замеры» — только фактические точки, отметки замеров видны на линиях. Выбор общий для всех графиков,
  запоминается в браузере. Кривая ближе к курсору выделяется, остальные приглушаются.
- Точку можно навести и исключить щелчком с запасом 14 px; Ctrl + колесо — масштаб, перетаскивание — сдвиг, двойной щелчок — сброс.
- Палитра проверена на дальтонизм; модули по-прежнему отдают цвета 5.8 (`atlas/engine/core/config.py COLORS`), экран и выгрузка
  (`atlas/render.py`) заменяют их по номеру одинаково.
- Общее перекрестие: наведите на дату в одном графике, и та же дата отмечена на всех графиках страницы с той же осью X.
  Щелчок закрепляет подсказку (до трёх, нумеруются, со второй показана разница с первой), Esc или × — открепить.
- Названия правых шкал Y при двух и более правых шкалах переносятся в полосу оси (до трёх строк, дальше «…», полное название — во всплывающей подсказке), единицы всегда отдельной строкой целиком (`fitAxisName`, `chartAxes.ts`). В выгрузке PNG/SVG/PDF названия повёрнуты вдоль осей и не пересекаются.
- Ползунок времени под рядами длиннее полугода: видны весь период и выбранное окно, края и середину можно тянуть.
- События на оси времени: `Chart.events` (`Event`: дата, подпись, вид `regime` / `gdi` / `repair` / `other`). Модули берут их из
  данных (`atlas/modules/_events.py`: начало отбора и закачки, даты ГДИ); попадают и в подсказку у курсора. Вид можно скрыть в легенде.
- Легенда по рядам: `Series.facets` ({'Скважина': '№ 31', 'Период': '2024-2025'}). Щелчок по значению скрывает все серии с ним,
  двойной щелчок — оставляет только его. В «Производительности» цвет — скважина, стиль линии — период.
- `Result.summary` (`Stat`) — строка итогов над графиками: скважины, период, средний расход, исключённые точки.
- Тёмная тема (переключатель внизу меню; роли цветов — CSS-переменные `--chart-*` и общие в `styles.css`), свёртка панели
  параметров в строку-сводку, свёртка меню, Ctrl+K — поиск раздела, в таблицах закреплён первый столбец и есть полоски значений.
- Больше 5000 точек в серии: облако рисуется пакетно, линия — с прореживанием LTTB; подсказка ищет по полным данным
  двоичным поиском, миллион точек не тормозит наведение.

## Разделы, которых нет в 5.8

- **Проверка данных** (`modules/quality.py`, поиск — `atlas/quality.py`): Рзаб не ниже Рпл, ΔP² не сходится с давлениями, скачки дебита,
  нули посреди отбора, повторы дат, пропуски, давление в других единицах. Ничего не исключается само: находки отмечаются флажками
  и исключаются тем же журналом, что и точки на графиках. Тот же отчёт показывается при проверке файлов перед сохранением импорта.
- **Динамика коэффициентов ГДИ** (`modules/gdi_trend.py`): a, b и расход при общем ΔP² по датам; рейтинг скважин по изменению
  отдачи между первым и последним надёжным исследованием. Математика — `gdi_history` из 5.8 (`tests/atlas/test_gdi_trend.py`).
- **Копии данных** — на странице «Проекты»; **мастер первого запуска** — `web/src/FirstSteps.tsx`.
- Кнопка **«?»** у параметра: `Param(formula=..., example=...)`. **«Копировать»** у графика кладёт в буфер тот же PNG, что и «Скачать».
- **Конструктор графиков** (`modules/builder.py`, интерфейс `web/src/ChartBuilder.tsx`; план этапов — `chart-builder/plan.md`): слева дерево
  полей по категориям с поиском (`POST /api/modules/builder/catalog` — только числовые и датовые поля, которые есть в данных проекта),
  ряды-карточки (набор и поле Y, поле X — дата или число, скважины, режим, период, ось Y1–Y5, линия или точки), справа обычный `ChartView`.
  X из другого набора сопоставляется по ключу ряда: «скважина + дата» (по умолчанию), «дата», «скважина», «ближайшая дата ±N дней»;
  несколько значений X на ключ — среднее, число пар пишется в заметке. «Нет данных» — пропуск (на линии разрыв), нули простоя — точки;
  линия по датам рвётся на перерывах дольше 7 суток. Заголовок и подписи осей — из полей и единиц, любое меняется вручную.
  Макет — параметр `layout` (вид параметра `json`), хранится и сохраняется («Сохранить макет») как параметры других разделов.
  Окна настройки (этап 2): кнопки «Ряд», «Ось», «График» над рядами открывают перетаскиваемые окна (`BuilderDialogs.tsx`), график меняется сразу;
  пустое поле — авто. Ряд — линия (цвет, толщина, сплошная/штрих/пунктир), маркеры (форма, размер, цвет), прозрачность (поля общие с окном
  «Настройка» — `SeriesLookFields` в `ChartSettings.tsx`); ось X и Y1–Y5 — подпись, минимум/максимум (у дат — даты), шаг, логарифм, обратная,
  с нуля, цвет, знаков после запятой или формат даты, шрифт и размеры; график — заголовок (текст, шрифт, размер, жирность, цвет, выравнивание),
  общий шрифт и цвет текста, легенда (снизу/сверху/справа/скрыть, шрифт, размер), сетка (обе/горизонтальная/вертикальная/нет, цвет), фон. Всё лежит
  в макете: `series[].look`, `axis_style`, `chart_style` (старые макеты без них открываются как раньше); проверка значений — `atlas/chart_style.py`
  (ошибка — понятный текст), результат — `Series.look`, `Axis.style`/`minimum`/`maximum`/`step`/`scale`, `Chart.style`. Тот же результат идёт в PNG/SVG/PDF/XLSX
  (`render.to_plotly` → `atlas/engine/core/export_style.py`); шрифты — из набора выгрузки (`times`, `arial_narrow`, `calibri`, стандартный). Размер шрифта на экране — px, в файле — пт
  (одно число). Заданный шаг оси отключает общую сетку делений при нескольких осях Y. Значок «Настройка» самого графика у конструктора скрыт: вид ряда задаётся в окне «Ряд».
  Комбинированные виды (этап 3): вид ряда (`row.view`) — линия, точки, линия с точками, столбцы, область, ступенчатая; любая комбинация на любой
  из осей Y1–Y5. В контракте новые виды — поля `Series.fill` (область = линия с заливкой) и `Series.step` (значение держится до следующей точки), `kind` не менялся;
  поле «Стопка» (`row.stack` → `Series.stack`) у столбцов и областей: одинаковое имя складывает их, у ряда на другой оси или другого вида стопка
  разводится отдельно (заметка), у остальных видов поле не действует. Ряды стопки приводятся к общему списку X (стопка в ECharts идёт по номеру точки).
  По скважинам: ряд с режимом «Текущая скважина» (`row.wells_mode`) берёт скважину макета (`layout.current_well`, выбирается над рядами кнопками и клавишами ←/→); `{скважина}` в заголовке, названии ряда и подписях осей
  заменяется номером; без выбранной скважины такой ряд не строится (заметка). «Серия по скважинам» выгружает график по каждой выбранной скважине (PNG в zip, PDF, Word с подписями «Рисунок N»; до 200 скважин, без данных — пропуск с перечнем).
  Поля необязательные: старые макеты и версия формата библиотеки не меняются; в отчёте АН макет «текущей скважины» без сохранённой скважины пропускается с предупреждением.
  Прозрачность в окне «Ряд» у области и столбцов — это заливка (по умолчанию 60 % у области). Слои: область и столбцы под линиями и точками
  (на экране `z`, в файле — прозрачные оси поверх, `export_combo.py`; только для `Chart.id == 'builder'`, `meta.combo`). Подсказка `chartHover.ts` у ступени
  даёт удерживаемое значение, у столбца — ближайший по X. XLSX: данные полные, но график в Excel рисует столбцы, области и ступени линиями.
  Ось X: `row.x_transform` (накопленное, ×/÷/+ число, разность) и `row.x_scope` (`curve` — как в наборе, `group` — сумма по группе скважины, `object` — сумма по объекту; давления усредняются) считаются по строкам X-набора до связи с Y; период ряда режет и X (накопленное идёт с начала периода). Если пар X и Y нет, заметка называет ключ связи, при котором пары находятся.
  Преобразования и формулы (этап 4, `modules/builder_calc.py`): `row.transform` — накопленное (сумма с начала периода; тыс. м³/сут → млн м³),
  скользящее среднее (N точек или суток), среднее/сумма/максимум/минимум по суткам, месяцам или по скважинам выборки (одна кривая), нормировка
  (на первую точку, максимум, число → «д. ед.»), ×/÷/+ число (известные переводы единиц: тыс. ↔ млн, кгс/см² ↔ МПа), разность соседних; считается
  по каждой скважине, пропуски не становятся нулями. `row.source = 'formula'`, `row.formula` — ряд из других рядов по буквам (A — ряд 1…, R27),
  `+ − × ÷ ^`, скобки, abs, sqrt, ln, log10 (lg), exp, min, max, mean, pi, e; свой разбор без `eval`, мусор, чужие имена и атрибуты — ошибка
  с номером ряда, циклы — ошибка. Точки формулы — точки первого её ряда, остальные подставляются по ключу `row.key` (скважина + дата по умолчанию;
  несколько на ключ — среднее); деление на ноль, логарифм и корень от недопустимого — пропуск со счётчиком в заметке. Скрытый ряд можно брать
  в формулу. `row.unit` — ручная единица. Экран проверяет формулу на лету (`web/src/builderFormula.ts`) и перенумеровывает буквы при удалении
  и дублировании рядов. Старые макеты без этих полей открываются как раньше.
  Макеты и выгрузка (этап 5, `builder_library.py`, `api_builder.py`, `web/src/BuilderLibrary.tsx`): блок «Макеты проекта» над рядами — список именованных макетов
  (сохранить как, обновить, открыть, переименовать, дублировать, удалить с подтверждением), файл JSON (`Экспорт/Импорт макета`, формат `gas-atlas-builder-layout`,
  версия 1; кривой файл — понятная ошибка, ничего не сохраняется). Хранение — `settings['builder_layouts'] = {version: 1, items: [{id, name, created, updated, layout}]}`
  в манифесте проекта: ключ необязательный, старые проекты (и 5.8) открываются как раньше. Макет с полем, набором или скважиной, которых нет в проекте, открывается
  с перечнем «что не найдено» (`missing_of`), остальные ряды строятся. Выгрузка: PNG/SVG/PDF — значок загрузки графика, «Данные XLSX/CSV» (`render.chart_csv`),
  Word одного графика с заголовком и подписью «Рисунок N – …» (поле SEQ; `POST /api/projects/{pid}/builder/word`, на `word_export.build_docx`). В отчёт «Авторский надзор»
  макеты идут параметром `builder_layouts` («Макеты конструктора в отчёте»): каждый — отдельный рисунок в конце графиков (`Chart.id = builder-<id>`), недостающие поля — заметками.
  Общее подключение к разделам — флаг `ModuleSpec(builder_layouts=True)` (параметр «Макеты конструктора», раздел «Вид», варианты — макеты проекта) и
  `builder_library.add_layout_charts(result, data, names, wells)`: графики после основных, `builder-<id>`, предупреждения вместо падения. Включено в «Производительности скважин»
  (режим «Отдельные скважины»: макет «Текущая скважина» — график на каждую выбранную скважину, до 12; в других режимах такой макет пропускается с заметкой);
  ГДИ и «Реагирование» — нет. Раздел работает с теми наборами, что и так загружает (`needs`/`optional` не расширяются): поля прочих наборов — заметка «нет данных набора».
- **Скорость**: `python tools/check_perf.py` сравнивает время каждого раздела на большом демо с бюджетом `tools/perf_budget.json`
  (в CI — задача `perf`); после намеренного изменения — `--update`.

- **Единая модель оформления** (`atlas/chart_style.py`, интерфейс `web/src/chartFormat.ts`; план — `/mnt/project-files/export-module/analysis.md`):
  документ `{chart, axes, series}` — поля графика (`CHART_FMT`), осей (`AXIS_FMT` + границы и деления текстом `AXIS_SCALE_KEYS`) и рядов (`LOOK`,
  ключ ряда «группа или имя|вид»). `clean_format` проверяет, `merge_formats` складывает уровни (поле позднего уровня главнее),
  `apply_format` кладёт документ в `Chart.style`, `Axis` (общая `style_axis`, ей же пользуются конструктор и «Любой график») и `Series.look`.
  Старые места переводятся `format_from_layout` (макет конструктора), `format_from_view` (вид с экрана), `format_from_any` («Любой график»);
  старые поля в проектах не меняются. Поля модели v2 (деления внутрь/наружу, линия оси, поворот подписей, единицы отображения, доп. шаг,
  пересечение, подзаголовок, легенда слева/колонки/рамка/фон, штрих сетки, рамки, граница и полый маркер, подписи данных, имя в легенде,
  штрихпунктир и длинный штрих) проверяются уже сейчас; экран и файлы рисуют их по мере переноса (PR 4 и 7 плана).
  Оформление проекта — настройка `chart_formats = {theme, types: {раздел: документ}}` (`clean_store`): тема действует на все графики, тип —
  на графики раздела. В файлы (график, архив раздела, «Любой график») его кладёт сервер (`compute(..., styled=True)` → `apply_store`),
  на экране — интерфейс; вид рядов окна «Настройка» — это `theme.series`, хранится в проекте (`web/src/projectLooks.ts`), вид из браузера
  Там же `templates: {имя: документ}` — шаблоны оформления («Шаблоны» в панели «Формат»: сохранить текущее, применить, перенести текстом JSON);
  на графики они сами не действуют. «Копировать формат / Вставить формат» в панели переносит оформление графика, оси или ряда на такой же элемент.
  прежних версий переносится в проект без своего оформления при первом открытии.

## Большие данные: прореживание и ускорения

* Результат модуля (`Result`) всегда хранит все точки. Прореживается только JSON для экрана (`atlas/thinning.py`, метод М4:
  первая, последняя, наибольшая, наименьшая точки участка и разрывы; пики и провалы сохраняются). Облака точек, столбцы, ящики не прореживаются.
* Прорежённая линия помечена над графиком: «Показано N из M точек». При увеличении (`POST /api/modules/{id}/window`) и в режимах
  «Замеры» и «Исключать точки» подгружаются все точки видимой области.
* Выгрузки графиков (PNG, SVG, PDF) считаются по всем точкам, таблицы CSV и XLSX — по полным таблицам; щелчок исключает точку по её идентификатору.
* Свёрнутые таблицы больше 20 000 строк отправляются при раскрытии (`POST /api/modules/{id}/table`).
* Многокривый график «Производительности» (больше 200 кривых) сопровождается предупреждением.
* Открытие проекта: сезоны считаются по различным сочетаниям, идентификаторы точек без промежуточной колонки, память оценивается выборкой,
  повторяющиеся строки хранятся одним объектом. Суточный набор «Поскважинного анализа» готовится в фоне после открытия большого проекта.


## Шрифты выгрузки

Графики выгружаются со шрифтом `default` (DejaVu Sans), `times` (Times New Roman) или `arial_narrow` (Arial Narrow), размер 5–20 пт (`font`, `font_size`; страница «Экспорт» и пакеты приложений). Если в системе есть оригинал (Windows), берётся он; иначе аналог из `atlas/fonts/`: Liberation Serif и Atlas Sans Narrow (Liberation Sans, сжатый до 82 % скриптом `tools/make_narrow_font.py`; SIL OFL 1.1, текст лицензии рядом). Шрифты лежат в git и попадают в портативные сборки вместе с `atlas/`. Шрифт `calibri` (аналог Carlito) и «Вид графиков: как диаграммы Excel» (`look=excel`: палитра Office, линии 2,25 пт, серый текст, горизонтальная сетка, легенда внизу) действуют в предпросмотре, архиве, Word и пакете приложений. Отчёты Word рисуются выбранным шрифтом экспорта.

Оформление графиков (`atlas/chart_format.py`, страница «Экспорт», сохраняется в шаблонах): общее для всех графиков — наклон подписей оси X, шапка, положение легенды (`fmt_angle`, `fmt_title`, `fmt_legend`); для наборов данных (кривых) каждого типа отдельно — цвет, толщина линии, размер маркеров (0 — без них), «скрыть» (`fmt_<модуль>_series`, правило по фрагменту названия из легенды; подсказки названий — `POST …/export/series`). Вид Excel заданные цвета и размеры не перебивает. Вкладка «Отдельные графики» страницы «Экспорт»: свои правила наборов данных и оси одного графика из семейства (`fmt_overrides`, JSON `{имя графика: {series, axes}}`), они сильнее настроек типа; сброс — по одному графику или все. «Пакет по фонду» и «ГГХ (Word)» — вкладки страницы «Экспорт» (`#/@pack` и `#/@ggh` открывают их); на них действуют шрифт, вид, размер шрифта, подписи и оформление (пакет — как график «Производительность», ГГХ — правила для «ГГХ»).


### Подписи оси X и наклон
При заданном наклоне подписей (Экспорт → «Подписи оси X») число подписей подбирается само: считается, сколько их помещается в ширину графика с учётом наклона (на 45° больше, чем на 0°, на 90° ещё больше), и берётся самый частый круглый шаг (день, месяц, год) без наложений. Заданные вручную деления оси X («Оси: границы и деления») имеют приоритет. `app/core/export.py: x_labels`.
