# Шлюзы данных и графиков

Для каждого шлюза итог: `ок`, `не проверено` или `нарушено` со ссылкой `файл:строка`.

## Как применять

- Только перед итоговой таблицей, графиком или прогнозом. Не при рабочих правках.
- Если `pxg-expert-panel` уже прошла по этим числам, её проверки (расчёты, единицы, датумы) не повторять: пройти только шлюзы 1, 3, 4, если они ещё не покрыты.
- Идти по порядку: ошибка данных делает остальные шлюзы бессмысленными.
- Проверять кодом или пересчётом, не намерениями. Пропущенное - `не проверено`.
- Субагент по шлюзу только если риск оправдывает расход; по умолчанию проверка в основном чате.
- Уровни: **блокер**, **улучшение**, **вкус**. Общие замечания без проверяемого содержания не принимаются.

## Шлюз 1. Качество данных

Сырое неизменяемо; молчаливая очистка запрещена; всё изменённое и отброшенное попадает в отчёт.

1. Схема входа описана типами; несоответствие - ошибка, не тихий `astype`.
2. Дубли по ключу (скважина + дата, скважина + глубина) найдены и учтены; дубли периода завышают добычу.
3. Время и глубина монотонны; календарные пропуски - простой, не ноль.
4. Единицы берутся из метаданных колонки; смешение m/ft, psia/barg, м³/bbl не проходит.
5. Физические границы: дебит >= 0 (кроме закачки), обводнённость [0,1] или [0,100] без смеси, давление и глубина > 0.
6. Sentinel `-999,25` превращён в null; null не равен 0 на всём пути к графику.
7. Согласованность сумм: скважины = группа = объект = узел учёта с допуском; расхождение объясняется.
8. Ловушки CSV/Excel: дата как текст, десятичная запятая, объединённые ячейки, пробел в тысячах, скрытые листы, формулы вместо значений.
9. Отчёт качества: входы с sha256 и числом строк, проверки со статусом, число отброшенных и изменённых значений.
10. Идемпотентность: повторный прогон не дублирует строки и даёт тот же результат.
11. Единицы приводятся один раз на слое curated; у агрегата есть источники, версия правил, хеш входа.
12. Интерфейс показывает пометку «данные неполные» рядом с данными.

## Шлюз 2. Семантика нефтегазовых данных

1. У каждой величины единица есть в имени поля, схеме, оси и таблице.
2. Газ: стандартные условия указаны и едины.
3. Глубина: MD, TVD, TVDSS, GL/RT; отметка ниже уровня моря со знаком минус.
4. Давление: абсолютное или избыточное (разница около 14,7 psi), точка замера (WHP, FLP, затруб, пласт).
5. Темп и накопление - разные размерности, не на одной оси; нормировка объявлена.
6. Простои не интерполируются нулём и не закрываются линией.
7. Обводнённость - доля или проценты единообразно; выше 100 % - ошибка данных. WOR, GOR, CGR считаются из темпов одного интервала.
8. Префиксы: M = 10³, MM = 10⁶; штуцер в 1/64 дюйма.
9. Запасы: P90 консервативна, P10 оптимистична; 1P, 2P, 3P названы; mean не равно P50.
10. DCA по Arps: b в [0,1]; nominal и effective различены; подгонка по темпу, а не по накопленной; остатки смотрятся, не только R²; у прогноза интервал и back-test.
11. Type curves нормированы до сравнения скважин. Округление не выше точности измерения.

## Шлюз 3. Статистика

1. Единица анализа названа (замер, сутки, скважина, пласт) и совпадает с уровнем агрегации.
2. Автокорреляция учтена: эффективный n, HAC или блочный bootstrap, не сырой p-value.
3. Стационарность проверена до регрессии; два растущих ряда дают ложно высокий R².
4. Разбиение train/test не пересекается по времени и скважине; для прогноза walk-forward; нет утечки будущего.
5. Множественные сравнения: число гипотез известно, поправка применена.
6. Результат = оценка + интервал + n; корреляция не причинность без контроля пласта, депрессии, штуцера, простоя.
7. Выбросы: физически невозможные отбрасываются с причиной; иначе робастные методы; правило записано.
8. Пропуски: механизм назван; интерполяция допустима для показа, не как вход регрессии; значения ниже порога обнаружения - цензурированные, не нули.
9. Дебиты и накопления скошены: медиана и квантили вместо среднего.
10. Смещение выжившего: сказано, какие скважины исключены. Проверен хотя бы один разрез (парадокс Симпсона).
11. MAPE на околонулевых дебитах завышается: показать распределение ошибок и ошибку по горизонтам.
12. Нелинейные пересчёты единиц делать до агрегации.
13. Воспроизводимость: seeds, версии, golden-тесты формул, сравнение float через допуск.

## Шлюз 4. Критика графиков

1. Вопрос одной строкой: какой вопрос инженера закрывает график; нет вопроса - это украшение.
2. Данные: источник, число точек, охват, фильтры.
3. Что график скрывает: простои, пропуски, разную историю, разные условия замера.
4. Форма: динамика - линия темпа, накопление отдельной панелью; сравнение скважин - отсортированный горизонтальный bar; распределение - гистограмма с ECDF; более 10 скважин - small multiples; неопределённость - fan chart P10-P90.
5. Антипаттерны (блокеры): двойная ось Y, обрезанная ось без пометки, круговая более чем на 4-5 секторов, 3D, jet/rainbow, красный/зелёный как единственный различитель, линия через пропуск, темп с накоплением на одной оси.
6. Пороги: более 15 категорий - top-N + «прочие»; более 5-7 линий - small multiples; более 10 000 точек - агрегация; разброс более 100 раз - лог-ось с подписью; ось bar с нуля.
7. Единицы, условия, датум, absolute/gauge на осях и в таблицах.
8. Неопределённость и n показаны; прогноз без интервала - не прогноз.
9. Заголовок несёт вывод, не название таблицы; три разных пустых состояния: нет данных, данные частичные, расчёт идёт.
10. График реально просмотрен как изображение (dpi >= 150): наложение подписей, обрезка осей, легенда, узкая ширина, тёмная тема; слишком ровная линия - признак интерполяции.
11. Доступность: подписи не только цветом, контраст не ниже 4,5:1.

Соглашения приложения: Python считает, TypeScript только отображает; число приходит с сервера вместе с единицей, датумом и точностью; отсутствие - `null`; ошибки расчёта не глотаются; новая метрика = функция + golden-тест + описание.

## Шлюз 5. Экономия токенов

1. Ответ начинается с вывода, масштаб ответа равен масштабу вопроса.
2. Файл не читать дважды; читать диапазоном после Grep; успешную команду не перезапускать.
3. Вывод команд ограничивать; независимые команды - одним вызовом.
4. Субагент стоит дорого: звать выборочно, узкие эксперты вместо широких.
5. Короткий CLAUDE.md, неиспользуемые MCP отключены, тяжёлое знание - в скиллах.
6. Между несвязанными задачами очищать контекст; модель и effort не менять посреди сессии.
7. Не экономить на проверках: резать пояснения, не корректность.

## Итоговый формат

Таблица шлюзов (шлюз, статус, число блокеров). Затем блокеры, улучшения по убыванию «эффект/стоимость», что сделано хорошо, чего не хватает, вопросы заказчику данных.
