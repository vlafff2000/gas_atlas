# Газовый атлас

Программа для анализа данных подземных хранилищ газа (ПХГ): динамика отбора и закачки, газодинамические исследования (ГДИ), реагирование горизонтов, кроссплот давлений, аналитика фонда скважин, паспорт скважины, экспорт графиков и таблиц. Работает локально, на одном компьютере; данные остаются в папке `storage/` рядом с программой.

Версия — **Атлас 6**: `atlas/` (ядро на Python) и `web/` (React, TypeScript, ECharts), окно приложения или браузер. Прежняя версия 5.8 (Streamlit) удалена; проекты, созданные в ней, открываются без миграции. Формат хранения без миграции не меняется.

## Требования

- CPython **3.8 или новее**, 64-bit (проверяется на 3.8, 3.11 и 3.13). Весь код обязан оставаться совместимым с 3.8: без `dict | dict`, `match`, `str.removeprefix`; аннотации через `from __future__ import annotations`.
- Интернет только для первой установки зависимостей. Node.js нужен лишь тому, кто меняет интерфейс: собранный интерфейс `atlas/web/dist` лежит в git.
- Без Python и без интернета: переносные архивы (см. ниже).

## Быстрый старт

Windows (распакуйте архив, например, в `C:\GasAtlas`):

1. `install_windows.bat` — создаст `.venv` и поставит зависимости.
2. `run_atlas_windows.bat` — Атлас 6 в окне.

Linux:

```bash
bash install.sh
bash run_atlas.sh        # Атлас 6 в браузере
```

Вручную: `python -m atlas` (окно), `python -m atlas --browser`, `python -m atlas --server` (только ядро, порт 8765). Свой Python для установки: `GAS_ATLAS_PYTHON` (Windows) или `PYTHON_BIN` (Linux); папка данных: `GAS_ATLAS_STORAGE`.

Для знакомства откройте демонстрационный объект («Открыть демонстрационный объект»). Для проверки скорости есть большой демо-объект на 2 млн строк: `python tools/make_large_demo.py` или кнопка в разделе «Проекты».

## Что умеет

Разделы Атласа 6 (в меню по умолчанию девять, остальные включаются в «Настройках»):

| Раздел | Назначение |
|---|---|
| Обзор | сводка по проекту и данным |
| Импорт данных | файлы и вставка из Excel, распознавание, проверка, применение; данные давлений для кроссплота |
| Производительность скважин | отбор и закачка, Q по дате и накопленному объёму, сезоны и годы |
| Гистограммы | распределения по эксплуатации скважин |
| ГДИ | подбор ΔP² = aQ + bQ², R², сравнение исследований, Qmax и Qсв |
| Графики реагирования | рабочие и контрольные горизонты, приведённое давление |
| Кроссплот давлений | сопоставление давлений по объектам, пороги, категории объектов |
| Поскважинный анализ, Паспорт скважины | всё по одной скважине, паспорт с комментарием и PDF |
| Аналитика фонда, Группы | рейтинг и качество исследований; группы и подгруппы скважин |
| Исключённые точки, История фильтра | исключение точек кликом, журнал, отмена и восстановление состояния |
| Экспорт | PNG/SVG/PDF, CSV/XLSX, общий ZIP с параметрами и журналом |
| Проекты, Настройки | проекты, копии, резервные копии, общие настройки |

Графики: подсказка с интерполяцией или только по замерам, общее перекрестие, закрепление подсказок, ползунок времени, события на оси, тёмная тема, Ctrl+K для поиска раздела.

## Устройство

```
atlas/            ядро Атласа 6
  contract.py       контракт модуля: ModuleSpec, Param, Result (Table, Chart, Note)
  registry.py       находит модули в atlas/modules/ сам
  modules/          по файлу на раздел; только выбор данных и представление
  api*.py           HTTP/JSON (Starlette): модули, проекты, импорт, экспорт, паспорт
  render.py         графики для экспорта (SVG/PDF/PNG)
  web/dist/         собранный интерфейс (в git)
web/              исходники интерфейса: React + TypeScript + ECharts
  engine/           расчётное ядро, унаследованное от 5.8 (без Streamlit)
    core/             хранение, импорт, исключения, экспорт, демо-данные
    modules/          проверенная математика (ГДИ, реагирование, группы и др.)
tests/            тесты расчётного ядра; tests/atlas — тесты API и модулей
docs/             документация, ADR, чек-листы переноса docs/parity/
tools/            установка, запуск, демо-данные, бенчмарк, сборка переносных архивов
examples/         образцы входных таблиц
```

Главный принцип: математика живёт в `atlas/engine/modules/` и не переписывается; модули `atlas/modules/` вызывают её и отвечают только за выбор данных и вид результата. Новый раздел добавляется одним файлом в `atlas/modules/`, интерфейс подхватывает его сам. Подробности — `docs/ATLAS6.md`, решение об архитектуре — `docs/adr/ADR-001-architecture.md`, история переноса — `docs/MIGRATION.md`.

## Разработка

```bash
python -m pytest -q tests                          # тесты Атласа 6
cd web && npm ci && npx tsc --noEmit && npm run build   # типы и сборка интерфейса
python -m atlas --server                           # ядро для разработки интерфейса
cd web && npm run dev                              # интерфейс с горячей перезагрузкой
```

Перед коммитом: тесты проходят, `atlas/web/dist` пересобран (CI сравнивает его с исходниками), новый интерфейс проверен в браузере. Чек-листы переноса из 5.8 остались в `docs/parity/` как история. Тексты для пользователя пишутся по-русски; пустая выборка — заметка, а не ошибка. Правила работы над репозиторием — `CLAUDE.md`.

CI (`.github/workflows/ci.yml`) обычно идёт на Python 3.8; три версии сразу — Actions → CI → Run workflow → `all_pythons`. Правки только в `docs/`, `*.md` и `storage/` CI не запускают.

## Переносные архивы

Для компьютеров без Python и интернета (в том числе РЕД ОС) собираются архивы со своим Python 3.8 и всеми пакетами:

- `Gas_Atlas_portable_windows_x64.zip` — Windows 7 SP1 – 11, запуск `Gas_Atlas_6.bat`;
- `Gas_Atlas_portable_linux_x64.tar.gz` — Linux x86_64 с glibc 2.17+ (РЕД ОС 7.3+, Astra, ALT), запуск `gas_atlas_6.sh`.

Сборка идёт вручную: GitHub → Actions → «Portable archives» → Run workflow (или пуш тега `v*`); локально — `python tools/build_portable.py windows|linux`. Подробности — `docs/PORTABLE.md`. При обновлении переносите папку `storage/` в новую распаковку.
