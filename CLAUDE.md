# Газовый атлас: правила работы над репозиторием

Версия 5.8 (Streamlit) удалена: остался **Атлас 6** (`atlas/` + `web/`), см. `docs/adr/ADR-001-architecture.md`. Расчётное ядро,
унаследованное от 5.8, лежит в `atlas/engine/` (core, modules). Как запускать, как устроено и как подключать модули — `docs/ATLAS6.md`.

## Контекст
Стек: Python-ядро (Starlette, `atlas/api.py`) + React/TS (`web/`); запуск — окно Windows-приложения (pywebview), на Linux в браузере. Порядок: каркас и контракт модулей (`atlas/contract.py`), затем перенос раздела за разделом. При переносе из 5.8 ни одна функция оригинала не теряется (чек-листы — `docs/parity/`).

## Расчёты
Проверенную математику (`atlas/engine/modules/`) не переписывай: в `atlas/modules/` — только выбор данных и представление. Изменение расчёта сопровождай тестом.

## Данные и единицы
Полный список правил — в скилле `pxg-expert-panel` (блок «Правила проекта»). Коротко: давления абсолютные; глубина ниже моря TVDSS со знаком минус; простой = строка с нулём, «нет данных» (-999,25) = пропуск; названия групп нормируются единой схемой («ГСП-1» = «ГСП 1»); выбор файлов — только общий проводник `atlas/fs_browse.py`.

## Совместимость
Проекты, исключённые точки, журнал и сохранённые виды лежат в `storage/`. Формат не менять без миграции: старые проекты (в том числе созданные в 5.8) должны открываться.

## Проверка перед коммитом
- `python -m pytest -q tests` (при узкой правке — только затронутые файлы)
- `cd web && npx tsc --noEmit && npm run build` — собранный интерфейс `atlas/web/dist` в git НЕ коммитится (в .gitignore; архивы собирают его в CI),
- новый интерфейс смотреть в браузере (`python -m atlas --server` и `npm run dev`), а не только по тестам.

## Экономия лимита
- Не читать файл целиком, если нужен фрагмент: Grep по месту, Read с offset/limit. Не перечитывать то, что уже в контексте.
- Большие данные (Excel, CSV, LAS) обрабатывать скриптом, выводить только итог и проверки.
- Длинные выводы не вставлять в чат: писать в файл и отдавать путь.
- Субагентов не запускать без прямой просьбы или явной необходимости. Панель экспертов — только по `/panel` или перед публикацией чисел; шлюз `pxg-data-and-chart-gates` — только перед итоговой таблицей, графиком, прогнозом.
- В конце не пересказывать выполненные шаги.
- Тесты и сборку не гонять повторно без новых правок.

## Порядок работы над разделом
Один раздел = один чат. В конце записать сводку в `docs/handoff/<раздел>.md` по `docs/handoff/TEMPLATE.md` (до 15 строк); следующий чат начинать с чтения этого файла.
Модель (рекомендация): рутинный перенос кода и UI — лёгкая модель (Haiku/Sonnet), расчёты и архитектура — сильная.

## Прочее
Тексты для пользователя — по-русски; пустая выборка — заметка, а не ошибка; работает на Python 3.12+ (обычный CI идёт на 3.13, на 3.12 и 3.13 — вручную, `all_pythons`; компьютеры компании на РЕД ОС 7.3 и Windows 10+, переносная сборка с Python 3.13 — `docs/PORTABLE.md`). Новые пакеты и обновления версий в `requirements-lock-py313.txt` — только если есть колёса manylinux2014 (glibc 2.17) под Python 3.13: numpy, scipy, pandas, pyarrow, pillow, contourpy выше закреплённых версий на РЕД ОС 7.3 не запустятся. `pandas.Series.str.*` с готовым `re.compile(..., re.I)` флаги игнорирует: передавайте строку с `(?i)` или `case=False`.
